# Grid Layout Mode for Panels

**Type:** Feature
**Priority:** Normal
**Effort:** Medium-Large

---

## TL;DR

Add a grid layout arrangement option alongside the existing horizontal (side-by-side) layout. Users can cycle through **vertical**, **horizontal**, and **grid** arrangements. Grid mode auto-calculates rows/columns based on visible panel count:

- **2 panels** → side by side (1×2)
- **3 panels** → 2 on top, 1 on bottom spanning full width
- **4 panels** → 2×2 perfect grid
- **5 panels** → 3 on top, 2 on bottom
- **6 panels** → 3×3 or 2×3
- ...and so on

---

## Current State

- Panels are arranged in a single horizontal row via `RootSplitViewController` using `NSSplitView`
- `SnapLayout` defines which panels are visible but always in a left-to-right arrangement
- No concept of vertical stacking or 2D grid arrangement exists

## Desired State

- A new arrangement mode (cycle: horizontal → vertical → grid) that controls how visible panels are laid out
- Grid mode computes `cols = ceil(sqrt(n))`, `rows = ceil(n / cols)` and wraps panels into rows
- Last row may have fewer panels that stretch to fill width
- The cycle toggle should be accessible via:
  - A button/control in the `LayoutBarView`
  - A keyboard shortcut
- Works with both preset `SnapLayout` and custom `CustomLayout` configs

## Relevant Files

- `totalcommander/UI/WorkspaceViewController.swift` — wires layout bar to split view
- `totalcommander/UI/LayoutBar/LayoutBarView.swift` — needs a cycle button for arrangement mode

---

## Notes

- The current `NSSplitView` only supports a single axis. Grid layout will likely require either nested split views (outer vertical split + inner horizontal splits per row) or a custom `NSView` container with constraint-based grid layout.
- Nested `NSSplitView` approach: outer split divides into rows (vertical), each row is a horizontal split view containing that row's panels. This preserves resize handle behavior.
- Layout icon previews in the bar should reflect the arrangement mode visually.
