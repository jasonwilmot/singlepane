# 27: Layout Button Hotkey Assignment via Right-Click

**Type:** Feature
**Priority:** Normal
**Effort:** Medium

## TL;DR

Let users right-click any layout button (preset or custom) to assign/remove a keyboard hotkey. Visual border style indicates hotkey status: solid = has hotkey, dotted = no hotkey.

## Current State

- Layout buttons (`LayoutIconView`, `CustomLayoutIconView`) have no hotkey support
- `LayoutIconView` has no right-click handler at all
- `CustomLayoutIconView` right-click only shows "Delete"
- All icons use the same border style regardless of any state beyond selection

## Expected Outcome

1. **Right-click any layout button** (preset or custom) shows a small popover/box:
   - **No hotkey assigned:** Shows a "Record" button. User presses it, then types their desired key combo. The recorded hotkey displays in the box. Confirm to save.
   - **Hotkey already assigned:** Shows the current hotkey + a "Delete" option. Deleting the hotkey returns the button to the "no hotkey" state (and the box then acts like the add-hotkey flow).
2. **Visual border differentiation:**
   - Layouts **with** a hotkey: **solid border** (the existing style)
   - Layouts **without** a hotkey: **dotted/dashed border**
3. **Hotkeys are global** within the app — pressing the combo activates that layout from anywhere
4. Custom layout right-click menu should add "Set Hotkey" alongside the existing "Delete" option

## Relevant Files

- `totalcommander/UI/LayoutBar/LayoutIconView.swift` — preset icons, needs right-click handler + border style logic
- `totalcommander/UI/LayoutBar/CustomLayoutIconView.swift` — custom icons, extend right-click menu + border style logic
- `totalcommander/UI/LayoutBar/LayoutBarView.swift` — may need to manage hotkey storage/persistence and wire up global key handlers

## Notes

- Hotkey bindings need persistence (UserDefaults or a plist keyed by layout identifier)
- Need a key event recorder view (NSView that captures the next key combo) — could be a small reusable component
- Preset layouts have stable identifiers via `SnapLayout` enum cases; custom layouts have UUIDs
- Consider conflict detection if user tries to assign a hotkey already used by another layout or system shortcut
- The dotted border for no-hotkey state needs to work with the existing selected/unselected color logic
