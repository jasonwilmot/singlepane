# Global Theming System with Ghostty-Compatible Presets

**Type:** Feature
**Priority:** Normal
**Effort:** Large

## TL;DR
A single global theme controls every color in the app — terminal ANSI palette, terminal foreground/background, tab bar, layout bar, file explorer, preview panel, dividers, text. Ship 8-10 popular presets matching Ghostty's most-used themes. Theme is app-wide, not per-panel.

## Current State
- All colors are hardcoded (`NSColor.controlAccentColor`, `.textColor`, `.textBackgroundColor`, etc.)
- Terminal uses SwiftTerm defaults via `configureNativeColors()`
- No way to change the look of the app

## Expected Outcome
- `Theme` struct defining every color slot (terminal palette + UI chrome)
- `ThemeManager` (@Observable) holds the active theme, persists selection
- All views read colors from `ThemeManager` — one switch recolors everything
- 8-10 bundled presets: Catppuccin Mocha, Dracula, Gruvbox Dark, Nord, Tokyo Night, Solarized Dark, One Dark, Rose Pine
- Theme switcher accessible from menu bar or layout bar
- Ghostty `.conf` theme import support (future, same color slots)

## Color Slots

### Terminal (per Ghostty/ANSI standard)
- `foreground`, `background`, `cursor`, `selection`, `selectionForeground`
- 16 ANSI colors: `black`, `red`, `green`, `yellow`, `blue`, `magenta`, `cyan`, `white` (normal + bright)

### UI Chrome (global)
- `chromeBackground` — tab bar, layout bar, toolbar backgrounds
- `chromeBorder` — dividers, separators
- `chromeText` — primary text in chrome areas
- `chromeTextSecondary` — dimmed/inactive text
- `chromeAccent` — selected tab, active layout icon, accent highlights
- `explorerBackground` — file list background
- `explorerText` — file list text
- `explorerSelection` — selected row highlight
- `previewBackground` — preview panel background
- `hookHighlight` — blended with hook colors for tab wash

## Implementation Notes
- `Theme` is a Codable struct with all color slots as hex strings
- Bundled themes are JSON files in the app bundle
- `ThemeManager` is an `@Observable` singleton on `@MainActor`
- SwiftTerm colors set via `nativeForegroundColor`, `nativeBackgroundColor`, `installColors(_:)` for the 16 ANSI palette
- UI views observe `ThemeManager` and update on change (same `withObservationTracking` pattern used in file explorer)
- Active theme persisted in UserDefaults (just the theme name)

## Risks / Notes
- Large surface area — every view needs to read from ThemeManager instead of hardcoded colors
- Should be done in one pass to avoid half-themed UI
- Ghostty theme files use a simple `key = value` format, easy to parse
- Could add theme preview (live swap) in a future iteration
