# Layout Manager Modal

**Type:** Feature
**Priority:** Normal
**Effort:** Large

---

## TL;DR

Replace the flat layout icon strip with a dropdown modal/sheet that consolidates panel ordering, layout selection, hotkey management, and custom layout creation into one unified surface.

---

## Current State

- Layout bar (`LayoutBarView`) is a horizontal strip of small layout icons + a divider + custom layout icons + a "+" button.
- Clicking an icon immediately applies that layout.
- Hotkey recording/deletion has no UI surface in the layout bar — it lives only in `LayoutHotkeyManager`.
- Panel column order is changed via shift arrows inside each panel header, not from the layout bar.
- Custom layout "+" button sits inline in the strip.

## Expected Outcome

Clicking any layout icon (or a dedicated trigger) opens a **modal/sheet** with three sections:

### 1. Panel Order Row (top)
- Three horizontal draggable icons representing **Terminal**, **Explorer**, **Preview/Editor**.
- User drags to reorder — the actual panel layout updates **live** on drop.
- Column order persists globally via `LayoutConfiguration.saveColumnOrder()`.
- Modal stays open after reorder.

### 2. Layout Grid (middle)
- All 7 preset `SnapLayout` icons displayed.
- All saved `CustomLayout` icons displayed below (or alongside).
- Each layout row/item shows:
  - The layout icon (same visual as current `LayoutIconView` / `CustomLayoutIconView`).
  - A **hotkey pill** showing the bound shortcut (e.g., "⌃⌥1"), or a **"Record Hotkey"** button if none assigned.
  - A **delete hotkey** icon (x) next to existing hotkey pills.
- Clicking a layout icon → applies the layout **and closes the modal**.
- Recording or deleting a hotkey → does **not** close the modal.

### 3. Add Custom Layout (bottom)
- A "+" button inside the modal to save current layout as a custom preset.
- The existing "+" button in the layout bar **remains** outside the modal as well.
- Both do the same thing: `delegate?.layoutBarDidRequestSaveCustomLayout()`.

### Modal Behavior
- Has a close button (X) to dismiss without selecting a layout.
- Clicking a layout icon = apply + auto-close.
- Hotkey record/delete = stays open.
- Panel reorder drag-drop = stays open.

## Notes / Risks

- **Drag-and-drop in a sheet**: AppKit sheets can be tricky with drag-and-drop. May need to use an `NSPanel` or a child window instead of `beginSheet` if drag sessions don't work inside sheets.
- **Live panel reorder**: The column order change must propagate to the root split controller while the modal is still open. Need to ensure the delegate chain supports this without dismissing.
- **Hotkey recording UX**: Need a "listening for keypress" state on the record button — similar to macOS System Preferences shortcut recording. Should handle conflicts (already bound to another layout) with inline feedback.
- The existing inline layout bar icons could either remain as-is (clicking opens the modal) or be simplified to just show the currently active layout + a dropdown arrow. TBD on exact trigger UX.
