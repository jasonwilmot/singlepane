# Editor Status Bar

**Type:** Feature
**Priority:** High
**Effort:** Medium

---

## TL;DR

Add a status bar to the bottom of the editor/preview panel showing cursor position, file encoding, line endings, indentation style, and file type. Each element should be clickable to change its value. This is the foundation for encoding detection, line ending detection, and wrap toggle — without it, those features have nowhere to surface.

---

## Current State

- Editor view (`EditorViewController`) fills to the bottom of its container with no bottom chrome
- No cursor position display (line/column)
- Encoding hardcoded to UTF-8 — no detection, no display
- Line endings (LF/CRLF) not detected or displayed
- Indentation style detected internally (`detectIndentUnit`) but not shown to user
- File type known internally (`currentLanguage`) but not displayed

## Desired Outcome

A thin status bar (~20-22px) anchored below the editor/preview content area showing:

```
Ln 42, Col 17  |  UTF-8  |  LF  |  Spaces: 4  |  Swift
```

- **Cursor position** (`Ln X, Col Y`) — updates on selection change
- **Encoding** (`UTF-8`, `UTF-16`, `Latin-1`, etc.) — clickable to change encoding
- **Line endings** (`LF`, `CRLF`, `CR`, `Mixed`) — clickable to convert
- **Indentation** (`Spaces: 4`, `Tabs`) — clickable to change
- **File type/language** (`Swift`, `JSON`, `Markdown`) — display only (or clickable to override)
- **Selection info** — when text is selected, show character/line count (e.g., `3 lines, 47 chars`)

### Design Notes

- Theme-aware: background from `chromeBackground`, text from `chromeTextSecondary`
- Font: same monospace font at ~10-11px
- Visible in both Editor and Preview modes (Preview can show fewer items — just file type + encoding)
- Follows VS Code / CotEditor status bar conventions
- Left-aligned: cursor position, selection info
- Right-aligned: encoding, line endings, indentation, file type

---

## Dependencies / Enables

This ticket is a prerequisite for:
- Encoding detection and conversion (needs somewhere to display detected encoding)
- Line ending detection and conversion (needs somewhere to display LF/CRLF)
- Word wrap toggle (could add a wrap indicator to the status bar)

## Risks

- Adding a view below the editor reduces vertical content space by ~22px — minimal impact
- Clickable elements need popover menus for encoding/line-ending/indent changes — can start display-only and add interactivity later
