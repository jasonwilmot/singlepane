# Swappable Panel Content with Shift Icons

**Type:** Feature
**Priority:** Normal
**Effort:** Medium

---

## TL;DR

Let users swap what content lives in each of the 3 main columns (terminal, explorer, preview) by clicking directional arrow icons in each panel's header bar. Currently panels are fixed to their positions.

---

## Current State

- `LayoutConfiguration.columnOrder` defines panel order (`[.terminal, .explorer, .preview]`) but there's no UI to reorder them at runtime.
- Panel types are fixed at their positions — no shift/swap controls exist in the panel headers.
- `RootSplitViewController` builds split items from `columnOrder` but only at init/layout-apply time.

## Desired Outcome

- Each panel header gets directional shift icons (right-aligned in the header bar):
  - **Left panel**: right arrow icon only (shift content right)
  - **Center panel**: left and right arrow icons (shift content either direction)
  - **Right panel**: left arrow icon only (shift content left)
- Clicking an arrow swaps the content of that panel with the adjacent panel in that direction.
- The swap should update `LayoutConfiguration.columnOrder` and re-render without full teardown (animate if possible).
- Persist the new order so it survives app restart.

## Implementation Notes

- Swapping means exchanging the panel types in `columnOrder` (e.g., clicking right on terminal swaps `[.terminal, .explorer, .preview]` -> `[.explorer, .terminal, .preview]`).
- Arrow icons should only appear on hover or always be subtle (match existing header bar styling).
- When a panel is collapsed/hidden, the visible panels' arrows should adapt accordingly.

---

## Relevant Files

- `singlepane/App/LayoutConfiguration.swift` — `columnOrder` and `PanelType` enum
- `singlepane/UI/RootSplitViewController.swift` — builds/manages the 3-column split
- `singlepane/UI/WorkspaceViewController.swift` — orchestrates layout and panel creation

---

## Risks / Notes

- Need to handle edge cases when panels are collapsed (only 2 visible — arrows should reflect actual neighbors, not hidden ones).
- Swapping should preserve panel state (terminal sessions, explorer path, preview content) — swap the view controllers, don't recreate them.
- Consider whether this interacts with the existing layout preset/snap system in `LayoutBarView`.
