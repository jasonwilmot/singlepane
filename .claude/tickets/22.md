# System Notification on Stop/Notification Hook Events

**Type:** Feature
**Priority:** Normal
**Effort:** Small-Medium

---

## TL;DR

Fire a native macOS system notification (`UNUserNotificationCenter`) when a `stop` or `notification` hook event is received via the `totalcommander://hook` URL scheme. Clicking the notification should activate the app and switch to the terminal tab that triggered it.

---

## Current State

- Hook events (`stop`, `notification`, `prompt`, `agent`) arrive via URL scheme and update tab visuals (highlight color, spinner) + play audio
- No system-level notification is fired — if the app is in the background or the user is focused elsewhere, they have no way to know a task finished

## Expected Outcome

- When a `stop` or `notification` hook event arrives, fire a macOS notification via `UNUserNotificationCenter`
- Notification should include context (e.g. tab title or session name)
- Clicking the notification should:
  1. Bring the app to the foreground (`NSApp.activate`)
  2. Navigate to / select the terminal tab associated with that session UUID
- Respect system notification permissions (request on first use)
- Optional: suppress notification if the app is already frontmost and the relevant tab is visible

---

## Relevant Files

1. **`totalcommander/App/AppDelegate.swift`** — Hook URL parsing and event dispatch. Add `UNUserNotificationCenter` setup and notification posting here.
2. **`totalcommander/UI/WorkspaceViewController.swift`** — `handleHookEvent()` dispatch. May need to trigger notification from here or pass through to a notification service.
3. **`totalcommander/Terminal/TerminalContainerViewController.swift`** — Tab lookup by session UUID. Notification click handler needs to call into this to select the right tab.

---

## Implementation Notes

- Use `UNUserNotificationCenter` (not deprecated `NSUserNotification`)
- Store the session UUID in the notification's `userInfo` so the click handler can route to the correct tab
- Implement `UNUserNotificationCenterDelegate.userNotificationCenter(_:didReceive:withCompletionHandler:)` in AppDelegate to handle click-through
- Consider a user preference to enable/disable these notifications (some users may only want audio)
- Consider suppressing notifications when the app is active + relevant tab is focused (avoid noise)
