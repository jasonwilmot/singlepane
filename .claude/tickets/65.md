# Tabbed File Preview / Editing (VS Code-style)

**Type:** Feature
**Priority:** High
**Effort:** Large

---

## TL;DR

Add VS Code-style file tabs to the preview/editor panel. Selecting a file opens it in a new tab above the preview content. Each tab uses the same tab bar component and shortcuts as file explorer and terminal tabs. The preview/edit UI (read mode, editor, save/outline buttons) renders below the tab bar.

---

## Current State

- `PreviewContainerViewController` shows a single file at a time with a compact tab bar that only toggles between Preview/Editor modes for the *same* file
- Selecting a new file replaces the current preview — no way to keep multiple files open
- File explorer and terminal panels already support multi-tab workflows via `TabBarView`

## Desired Outcome

- Selecting a file in the file explorer opens it as a new tab in the preview panel (or focuses an existing tab if already open)
- Multiple files can be open simultaneously, each in its own tab
- Tab bar uses the same `TabBarView` component with full style (close button, status indicator)
- Same keyboard shortcuts for tab management (new, close, cycle, reorder) as file explorer/terminal tabs
- Each tab maintains its own state: file reference, preview vs edit mode, scroll position, unsaved changes indicator
- "Preview" tabs (single-click) are ephemeral and get replaced by the next selection (italic title, like VS Code); double-click or editing pins the tab
- Unsaved changes shown via dot/asterisk on tab, with save prompt on close

- `singlepane/UI/TabBar/TabBarView.swift` — Reuse as-is for the preview tab bar (switch from compact to full style)

- `singlepane/UI/FileExplorer/TabbedFilePaneViewController.swift` — Reference implementation for how file explorer manages tabs; follow same pattern

---

## Implementation Notes

- Follow the `TabbedFilePaneViewController` pattern: maintain an array of preview states (file URL, mode, scroll position, dirty flag) with one active tab
- Switch `TabItemView` style from `.compact` to `.full` in the preview tab bar
- Ephemeral "preview" tab behavior: track whether a tab is pinned; single-click file selection reuses the unpinned tab, double-click or first edit pins it
- Tab title = filename, tooltip = full path
- Dirty indicator (asterisk/dot) for unsaved editor changes — prompt on close
- Keyboard shortcuts should mirror file explorer tab shortcuts for consistency
