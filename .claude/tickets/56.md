# Performance Optimization Pass — App & Terminal Snappiness

**Type:** Improvement
**Priority:** High
**Effort:** Large (multiple focused sessions)

---

## TL;DR

The app has several concrete performance bottlenecks in file browsing, terminal rendering, file operations, and app launch. Fixing these will make scrolling, copying, terminal interaction, and startup feel noticeably snappier.

---

## Current State

- File icon fetched from `NSWorkspace.shared.icon(forFile:)` on **every cell render** — no caching
- Folder SF Symbol image + config object recreated per row
- Font `.withSize(12)` allocated per cell render
- Full `reloadData()` on any theme/font change (nuclear rebuild, loses scroll position)
- Conflict resolution uses repeated `fileExists()` calls — O(n) stat syscalls per batch
- No `clonefile(2)` for same-volume APFS copies — full byte copy instead of instant COW
- Terminal link scanner fires every 0.5s on a timer, even when idle
- Theme JSON files (16) loaded synchronously on main thread at launch
- OSC 133 callbacks wrapped in unnecessary `Task { @MainActor }` per event

## Expected Outcome

- Smooth scrolling through 10K+ file directories with no stutter
- Terminal feels immediate under all workloads
- File copies on APFS are near-instant (COW)
- Cold launch shaves 50-200ms
- Batch file operations don't slow down with naming conflicts

## Specific Optimizations

### HIGH Priority

| # | What | File | Lines | Impact |
|---|------|------|-------|--------|
| 1 | **Cache file icons** — NSCache keyed by file extension/UTType, async load with placeholder | `FilePanelViewController.swift` | 441 | Eliminates scroll stutter |
| 2 | **Incremental table updates** — replace `reloadData()` with `reloadRows(at:with:)` for theme/font changes | `FilePanelViewController.swift` | 195-268 | No flicker, preserves scroll position |
| 3 | **Batch conflict detection** — build `Set<String>` of existing filenames, check O(1) instead of looped `fileExists()` | `FilePanelViewController.swift` (540-550), `FileService.swift` (164-200) | Fast batch paste/copy |

### MEDIUM Priority

| # | What | File | Lines | Impact |
|---|------|------|-------|--------|
| 4 | **Cache folder image** — store configured `folder.fill` SF Symbol as a static/lazy property | `FilePanelViewController.swift` | 432-437 | Eliminates per-row alloc |
| 5 | **Cache font** — pre-compute `activeFont.withSize(12)`, update only on font change | `FilePanelViewController.swift` | 425 | Eliminates per-row font alloc |
| 6 | **Debounce terminal link scanner** — trigger on PTY output, not 0.5s timer | `TerminalContainerViewController.swift` | ~1230 | Eliminates idle CPU work |
| 7 | **Use `clonefile(2)` for same-volume APFS copies** — fall back to `copyItem` for cross-volume | `FilePanelViewController.swift` | 557 | Near-instant large file copies |
| 8 | **Lazy-load themes** — load only active theme at startup, defer others | `ThemeManager.swift` | 30-40 | Shaves 50-200ms off cold launch |

### LOW Priority

| 10 | **LRU metadata cache** — cache stat results keyed by (inode, mtime), invalidate via FSEvents | `DirectoryEnumerator.swift` | — | Avoids re-stat on re-sort/filter |

## Risk / Notes

- `clonefile(2)` only works on APFS same-volume — need volume detection logic
- Incremental table updates require tracking which rows changed (diff the items array)
- Icon cache needs invalidation strategy for custom file icons (rare but possible)
- Link scanner debounce needs care to not miss links on rapid output bursts
