# Custom Layout Save & Restore

**Type:** Feature
**Priority:** Normal
**Effort:** Medium

---

## TL;DR

Add the ability for users to save their current workspace layout as a custom preset, restore it with one click, and manage (rename/delete) saved layouts via a context menu.

---

## Current State

- 7 hardcoded `SnapLayout` presets in the layout bar (all equal, single panel, dual combos)
- No way to save a custom arrangement (e.g. specific panel widths, visibility combos beyond presets)
- Users who manually tweak layouts lose them when switching presets

## Desired Outcome

- A **"+" button** appears at the end of the preset layout icons (after a subtle divider)
- Clicking "+" saves the current layout state as a new custom preset
- Custom presets appear as layout icons in the same visual style as existing `LayoutIconView`, but with a **small number badge** (1, 2, 3...) overlaid to distinguish them from built-in presets
- **Click** a custom preset icon to restore that exact layout
- **Right-click** a custom preset icon for a context menu: Rename, Delete
- Cap at **5 custom layouts** to keep the bar clean; "+" button disables/hides when at capacity
- Custom layouts persist across app restarts (encode to disk via `Codable`)

---

## UX Details

- Subtle vertical divider (1px, `chromeBorder` color) between preset icons and custom icons
- Custom layout icons use the same 30x18 drawing style but with a small number badge (bottom-right corner, ~8px circle with number)
- Tooltip shows the custom name (default: "Custom 1", "Custom 2", etc.)
- Right-click context menu items: **Rename** (inline text field or sheet), **Delete** (with confirmation)
- When saving, capture: panel visibility, column order, panel width ratios, terminal tab orientation
- "+" button styled as a small bordered icon with SF Symbol `plus` or a simple "+" glyph, same height as layout icons

---

## Data to Capture Per Custom Layout

- `columnOrder: [PanelType]`
- `panelVisibility: [PanelType: Bool]`
- `terminalTabOrientation: TabOrientation`
- `panelWidthRatios: [PanelType: CGFloat]` (new — relative widths at time of save)
- `name: String` (user-editable)
- `createdAt: Date`

---

## Relevant Files

- `totalcommander/App/SnapLayout.swift` — preset layout enum; custom layouts will be a parallel model (struct, not enum)
- `totalcommander/UI/LayoutBar/LayoutBarView.swift` — add "+" button, divider, and custom icon views to the stack
- `totalcommander/UI/LayoutBar/LayoutIconView.swift` — extend or subclass for number badge drawing
- `totalcommander/App/LayoutConfiguration.swift` — extend with `panelWidthRatios` and use as the persistence model for custom layouts

---

## Implementation Notes

- Custom layouts should be a `[CustomLayout]` array persisted to `~/Library/Application Support/Velocity/custom-layouts.json` (or UserDefaults for simplicity)
- `CustomLayout` struct: wraps `LayoutConfiguration` + `name` + `id` (UUID)
- `LayoutBarView` needs a new section after the preset loop: divider + custom icons + "+" button
- `LayoutBarDelegate` needs a new method: `layoutBarDidSelectCustomLayout(_ layout: CustomLayout)`
- Restoring a custom layout means applying both visibility AND width ratios (current presets only set visibility with equal widths)
- The "+" button should briefly flash or the new icon should animate in to confirm save

---

## Risks / Notes

- Panel width ratios are not currently tracked in `LayoutConfiguration` — need to add this and wire it to `RootSplitViewController`'s divider positions
- Need to decide if custom layouts also capture terminal split state or just the top-level panel arrangement (recommend: top-level only for v1)
