# 031: Find and Replace in File Editor

**Type:** Feature
**Priority:** P1
**Effort:** Small–Medium
**Labels:** Editor, UX, Keyboard-First
**Phase:** 1 — Foundation (MVP)

## TL;DR

The `EditorViewController` (the editable text view for files) has no find or replace support. Users expect Cmd+F (find) and Cmd+Option+F (find and replace) to work in any text editor. This is a table-stakes feature for file editing.

## Current State

- `EditorViewController` uses `NSTextView` but does not enable `usesFindBar` or `NSTextFinder`.
- Pressing Cmd+F in the editor does nothing.
- No replace functionality exists anywhere in the app for file editing.
- The read-only `CodePreviewViewController` also lacks a find bar (tracked separately in ticket 007).

## Expected Outcome

- **Cmd+F** opens a find bar within the editor scroll view.
- **Cmd+Option+F** opens find and replace bar.
- **Cmd+G** / **Cmd+Shift+G** cycle through matches (next/previous).
- Incremental (live) search highlighting as the user types.
- Replace single match and replace all support.
- Escape dismisses the find bar and returns focus to the editor.
- Find bar styling respects the current theme (dark/light mode).

## Implementation Approach

Use **NSTextView's built-in `NSTextFinder` integration** — this is the macOS best practice and avoids reinventing the wheel:

1. **Enable the find bar on `NSTextView`:**
   - Set `textView.usesFindBar = true`
   - Set `textView.isIncrementalSearchingEnabled = true`
   - The enclosing `NSScrollView` automatically hosts the find bar

2. **Wire up standard menu actions:**
   - `performTextFinderAction(_:)` with `.showFindInterface` for Cmd+F
   - `.showReplaceInterface` for Cmd+Option+F
   - `.nextMatch` / `.previousMatch` for Cmd+G / Cmd+Shift+G
   - These should already work if the NSTextView is first responder and `usesFindBar` is enabled

3. **Theme the find bar:**
   - NSTextFinder's find bar inherits the window appearance by default
   - Verify it looks correct in both light and dark mode
   - If custom styling is needed, override via `NSAppearance` on the scroll view

4. **Coordinate with PreviewContainerViewController:**
   - `PreviewContainerViewController` already has a `contentFindBar` reference — ensure the editor's built-in find bar doesn't conflict with any existing find bar wiring
   - When switching between editor and preview modes, dismiss any active find bar

5. **Undo integration:**
   - Replace operations should integrate with the existing `allowsUndo = true` undo manager
   - A "Replace All" should be a single undoable action (group replacements in an undo group)

## Files to Modify

- `singlepane/UI/Preview/EditorViewController.swift` — Enable `usesFindBar`, `isIncrementalSearchingEnabled`, and verify menu action routing
- `singlepane/UI/Preview/PreviewContainerViewController.swift` — Coordinate find bar visibility when switching between editor/preview modes

## Risks / Notes

- NSTextFinder handles most of the heavy lifting natively — this should be a relatively small change
- Verify that syntax highlighting is preserved after replace operations (re-highlight affected ranges)
- The markdown mode (no line numbers, paragraph indentation) should also support find/replace
- Large file editing: ensure find doesn't freeze the UI on very large files — NSTextFinder handles this well natively but worth verifying
- Ticket 007 (find bar in CodePreviewViewController) is related but separate — that's find-only in read-only mode

- [ ] Cmd+G / Cmd+Shift+G cycle through matches
