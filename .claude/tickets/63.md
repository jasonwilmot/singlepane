# Add Feedback Button with Supabase Backend

**Type:** Feature
**Priority:** Normal
**Effort:** Small–Medium

---

## TL;DR

Add a "Feedback" button to the layout bar (rightmost position, after the theme button) that opens a popover where users can submit free-text feedback. Feedback is stored in a Supabase table via REST API.

## Current State

- No way for users to submit feedback from within the app.

## Desired Outcome

### Button
- Text label "Feedback" in the layout bar, rightmost position (theme button shifts left).
- Background: `chromeAccent` at ~25% opacity (matches layout manager save button style, adapts to user-selected theme).
- Style: `bezelStyle = .inline`, `isBordered = false`, with `layer?.cornerRadius = 4`.

### Popover
- Matches layout manager popover style: `NSPopover` with `.transient` behavior, `NSViewController` subclass, vertical `NSStackView` inside scroll view, same padding/sizing constants.
- Contains:
  - A multi-line text field for feedback (required)
  - A "Send" button styled like the layout manager's "+ Save Current Layout" button (chromeAccent background)

### Submit Flow
1. User clicks Send.
2. Form is replaced by an `NSProgressIndicator` spinner (indeterminate, small) so the user knows it's submitting.
3. On success: spinner replaced by "Thanks!" label for 1.5 seconds, then popover auto-dismisses.
4. On error: spinner replaced by the form again with a subtle inline error message (e.g. "Couldn't send — try again"), using `hookRed` for the error text. Form stays open to retry.

### Client-Side Rate Limit
- After a successful send, disable the Feedback button for ~30 seconds to prevent spam.

### Table Schema (SQL to run in Supabase SQL Editor)

```sql
create table public.feedback (
  id uuid default gen_random_uuid() primary key,
  feedback_text text not null,
  app_version text,
  created_at timestamptz default now() not null
);

alter table public.feedback enable row level security;

create policy "Allow anonymous insert"
  on public.feedback
  for insert
  to anon
  with check (true);
```

- INSERT-only for anon role. No SELECT/UPDATE/DELETE via API.
- Anon key is safe to embed in the app — RLS is the security boundary.
- Dashboard access (service role) bypasses RLS for viewing submissions.
