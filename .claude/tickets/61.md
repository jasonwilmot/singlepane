# Search Results Not Streaming — Wire Up Diagnostics + Loading UX

**Type:** Bug / Improvement
**Priority:** High
**Effort:** Medium

---

## TL;DR

Search results are not appearing in the search panel. Need diagnostics logging to trace the pipeline, a spinner to indicate search activity, and verified streaming of results as they arrive. Search must feel instant.

## Current State

- Search mode activates (UI toggles to search table) but results never populate
- No visibility into where the pipeline is breaking — SearchService, IndexService, ViewModel, or UI binding
- No loading indicator — user has no feedback that search is running
- Unclear if AsyncStream from `SearchService` is producing results, or if `FilePanelViewModel.executeSearch()` is consuming them, or if UI observation is wired correctly

## Expected Outcome

1. **Diagnostics**: Structured logging at each stage of the search pipeline so we can trace exactly where results stop flowing:
   - SearchService: query received, mode selected (indexed vs raw), results yielded (count + timing)
   - IndexService: FTS5 query executed, rows returned
   - FilePanelViewModel: stream consumption started, batches received, `searchResults` array updated
   - UI: observation fired, table reloaded, rows rendered

2. **Spinner / Loading Indicator**: Visual feedback in the search panel while search is active:
   - Show spinner immediately when search begins
   - Keep spinner visible until first results arrive or search completes with zero results
   - Show "No results" state when search finishes empty

3. **Streaming Results**: Results must appear incrementally as they arrive:
   - Each batch from the AsyncStream should trigger a UI update
   - Table should grow as results stream in — not wait for completion
   - First results visible within 200ms (raw) or 50ms (indexed) per spec

## Files to Touch

- `singlepane/Services/SearchService.swift` — Add diagnostic logging at query entry, mode selection, and result yield points
- `singlepane/Services/IndexService.swift` — Add diagnostic logging for FTS5 query execution and row counts
- `singlepane/ViewModels/FilePanelViewModel.swift` — Add logging in `performSearch()` and `executeSearch()`; verify AsyncStream consumption; add `isSearching` state property
- `singlepane/UI/FileExplorer/FilePanelViewController.swift` — Wire up spinner overlay; observe `isSearching` state; verify `observeSearchResults()` triggers table reload on each batch

## Notes

- The 150ms debounce in `performSearch()` is fine but make sure it's not swallowing the actual search execution
- Check that `searchResults` property updates are happening on MainActor so AppKit observation fires
- AsyncStream batching (50 items/batch) should be preserved — just make sure each batch triggers a UI update
- Spinner should be lightweight — an `NSProgressIndicator` (indeterminate) centered in the search table area
