# Side-by-Side Terminal Splits

**Type:** Feature
**Priority:** Normal
**Effort:** Medium-Large

---

## TL;DR

Allow users to split the terminal area into multiple simultaneous panes (side-by-side or stacked), with no cap on the number of splits. Users initiate splits by Cmd+clicking multiple tabs. Default orientation is vertical (columns). A toggle icon switches between vertical (side-by-side) and horizontal (top/bottom) split orientation.

---

## Current State

- Terminal supports multiple sessions via tabs, but only one session is visible at a time
- `TerminalContainerViewController` manages a single `contentView` that shows the active tab's terminal

## Expected Outcome

- Cmd+click on terminal tabs to select multiple tabs simultaneously
- Selected tabs display as split panes in the terminal content area
- Split orientation (vertical / horizontal) is toggleable via an icon button in the tab bar or toolbar
- No limit on number of splits (though performance will naturally constrain this)
- Clicking a single tab (without Cmd) collapses back to single-pane view
- Each split pane remains fully functional (input, output, find, link detection, drag-drop)
- Splits resize proportionally when the container resizes
- Dividers between splits are draggable for manual sizing

## Relevant Files

- `totalcommander/Terminal/TerminalContainerViewController.swift` — main orchestration; needs multi-pane layout logic
- `totalcommander/Terminal/TerminalSessionManager.swift` — may need to track which sessions are "active/visible" vs just "selected tab"
- `totalcommander/UI/DividerSplitView.swift` — existing split view component; likely reusable for terminal splits

## Implementation Notes

- **Tab multi-select:** Cmd+click adds/removes tabs from a "visible set." The tab bar needs to visually indicate multi-selection (e.g., highlighted background on all selected tabs).
- **Split layout:** Use `NSSplitView` or the existing `DividerSplitView` to arrange N terminal views. Orientation toggle swaps `.vertical` / `.horizontal` on the split view.
- **Orientation toggle:** Small icon button (e.g., two vertical bars vs two horizontal bars) placed in the tab bar area. Default is vertical (columns). Persists preference per window or globally.
- **Focus:** One pane is "focused" at a time for keyboard input. Clicking a pane or using a shortcut (e.g., Cmd+Option+Arrow) moves focus between splits. Focused pane should have a subtle visual indicator (border highlight).
- **Performance:** Each split is a full `LocalProcessTerminalView` with its own PTY — already works this way per-tab, just now multiple are visible simultaneously.

---

## Risks

- High split counts (5+) may degrade terminal rendering performance — monitor frame rates
- Link detection monitors and event monitors currently assume a single visible terminal; will need to scope to focused pane
- Tab bar visual design needs to clearly communicate multi-select state vs single active tab
