# File Pane Tabs — Multiple Tabs Per File Explorer Pane

**Type:** Feature
**Priority:** High
**Effort:** Medium-Large

---

## TL;DR

Add tab support within each file explorer pane so users can open multiple directories as tabs in a single pane, matching the spec: "Two independent file panels, each with unlimited tabs."

## Current State

- `DualPaneExplorerViewController` creates two `FilePanelViewController` instances (top/bottom) — each shows exactly one directory with no tab support.
- `TabBarView` and `TabItemView` exist and are fully functional (used by the terminal), supporting add/close/select, horizontal/vertical orientation, theming, and font observation.
- Each `FilePanelViewController` owns one `FilePanelViewModel` with a single `currentDirectory`.

## Expected Outcome

- Each file explorer pane (top and bottom) has its own tab bar above the file list.
- Users can open new tabs (Cmd+T or "+" button) — each tab gets its own `FilePanelViewModel` with independent directory, navigation history, sort order, and selection state.
- Switching tabs swaps the visible `FilePanelViewController` content (or swaps the backing view model).
- Closing a tab removes it (minimum 1 tab per pane).
- Tab title reflects the current directory name of that tab.
- Tab bar reuses the existing `TabBarView` component for visual consistency with terminal tabs.
- Tab presets (save/restore named tab configurations) are a future enhancement, not required here.

## Implementation Approach

Introduce a **`TabbedFilePaneViewController`** that sits between `DualPaneExplorerViewController` and `FilePanelViewController`:

1. **`TabbedFilePaneViewController`** — new container that owns:
   - A `TabBarView` (reuse existing component)
   - An array of `FilePanelViewModel` instances (one per tab)
   - A single `FilePanelViewController` whose backing view model is swapped on tab switch (or multiple `FilePanelViewController` instances that are shown/hidden)
2. **`DualPaneExplorerViewController`** — updated to create two `TabbedFilePaneViewController` instances instead of two raw `FilePanelViewController` instances.
3. **Tab lifecycle:**
   - New tab: create a new `FilePanelViewModel` (default to same directory as current tab), add tab to bar
   - Close tab: remove the view model, update tab bar
   - Select tab: swap the active view model / view controller
4. **Tab title updates:** observe `currentDirectory` on each view model and update the corresponding tab title via `TabBarView.updateTabTitle(_:at:)`.

## Risks / Notes

- **Selection delegate wiring** — when tabs switch, the selection delegate on `DualPaneExplorerViewController` needs to re-wire to the newly active `FilePanelViewController` so the preview panel updates correctly.
- **Memory** — each tab holds a `FilePanelViewModel` with cached file items. Should be fine for reasonable tab counts but worth noting.
- **Keyboard shortcuts** — Cmd+T (new tab), Cmd+W (close tab), Ctrl+Tab / Ctrl+Shift+Tab (next/prev tab) should be wired up as part of this work.
