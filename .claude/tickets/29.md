# Terminal Grid Layout Inconsistent at Higher Pane Counts

**Type:** Bug
**Priority:** Normal
**Effort:** Medium

---

## TL;DR

When multiple terminal panes are open (7+), the grid layout produces unevenly sized panes. The last row can have fewer columns than the rest, causing it to stretch differently and look misaligned. Pane sizes should be consistent across all rows.

## Current Behavior

- Screenshot shows 7 terminals: top row has 4 panes, bottom row has 3 panes
- The bottom row's 3 panes stretch to fill the same total width as the top row's 4, making them visually wider
- The `%` prompt character is visible floating disconnected in some panes, suggesting odd sizing/rendering artifacts
- At higher counts the layout becomes increasingly unbalanced

## Expected Behavior

- All terminal panes should have consistent, uniform sizing regardless of grid position
- When the last row has fewer panes than the column count, those panes should match the column width of the rows above (not stretch to fill)
- Layout should look clean and predictable at any pane count (3 through 9+)

## Root Cause

`buildGridView` in `TerminalContainerViewController.swift` uses nested `NSSplitView`s — each row is an inner split that divides its full width equally among its children. When the last row has fewer children than other rows, each child gets proportionally more width. The `equalizeSplitView` helper equalizes within each row independently, but doesn't coordinate column alignment across rows.

`gridDimensions` uses `ceil(sqrt(n))` for columns, which is fine for the math, but the layout doesn't account for the partial last row needing column-aligned sizing.

## Relevant Files

- `singlepane/Terminal/TerminalContainerViewController.swift` — `buildGridView()` (~line 529), `equalizeSplitPanes()` (~line 591), `equalizeSplitView()` (~line 607)
- `singlepane/App/LayoutConfiguration.swift` — `ArrangementMode.gridDimensions()` (~line 57)

## Possible Approaches

1. **Spacer views**: Add invisible spacer views to pad the last row to match `cols`, so all rows have the same number of subviews and equalize identically
2. **Manual width constraints**: After equalization, force last-row panes to match the width of panes in the first row by setting explicit divider positions based on first-row column widths
3. **Replace NSSplitView grid with NSGridView or manual constraint-based grid**: Would give precise cell-level control but is a larger refactor

## Notes

- Option 1 (spacer views) is probably the simplest fix — just fill incomplete rows with empty `NSView`s so `equalizeSplitView` naturally produces uniform column widths
- The divider grip overlay logic (`installSplitDividerGrips`) would need to skip spacer panes
