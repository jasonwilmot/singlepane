# Quick File Creation

**Type:** Feature
**Priority:** Normal
**Effort:** Medium

---

## TL;DR

Add a quick file creation feature that lets users instantly create new files from a set of predefined templates. Start with 7 common developer file types, each with sensible default content. Accessible via breadcrumb bar `+` button and right-click context menu.

## File Types (Phase 1)

| Extension | Default Filename | Default Content |
|-----------|-----------------|-----------------|
| `.md` | `untitled.md` | `# untitled\n` |
| `.txt` | `untitled.txt` | Empty |
| `.json` | `untitled.json` | `{}\n` |
| `.yaml` | `untitled.yaml` | Empty |
| `.swift` | `untitled.swift` | `import Foundation\n` |
| `.py` | `untitled.py` | Empty |
| `.sh` | `untitled.sh` | `#!/bin/bash\n` (auto `chmod +x`) |

## UI Placement — Breadcrumb Bar Action Strip

The right side of the `BreadcrumbBarView` becomes a compact action strip with icon buttons. This area will house multiple actions over time:

```
[ / Users / jason / Projects / src  ···(ghost)···  ]  [🔍] [+]
  ← breadcrumb segments (left-aligned) →              ← action strip (right-pinned) →
```

- **`+` button** — New File (this ticket). Click shows NSMenu with 7 file types.
- **`🔍` button** — FAYT filter toggle (future ticket). Click reveals an inline filter text field that replaces/overlays the breadcrumb segments. Typing filters the file list in real time. Esc dismisses.

This placement is **per-pane** — in dual-pane mode each pane has its own action strip, so there's no ambiguity about which directory receives the new file or which list is being filtered.

The action strip should be implemented as a small `NSStackView` pinned to the trailing edge of the breadcrumb bar, with the breadcrumb segment container's trailing anchor constrained to the action strip's leading anchor (so segments don't overlap the buttons).

## Desired Behavior

- User triggers "New File" via `+` button in breadcrumb bar or right-click context menu "New File >" submenu
- An NSMenu appears showing available file types (with file-type icons via `NSWorkspace`)
- Selecting a type creates the file in the current directory with default content
- The new file's name immediately enters in-cell inline rename mode so the user can type a custom name
- If `untitled.ext` already exists, auto-increment: `untitled 2.ext`, `untitled 3.ext`, etc.
- After rename: Enter or click-away commits the new name (via `FileManager.moveItem`). Escape keeps the default `untitled.ext` name.
- No FSEvents yet — explicitly call `loadDirectory()` after creation, then select the new row and begin editing
- `.sh` files automatically get the executable bit set (`chmod +x`)

## Right-Click Context Menu

This ticket introduces the file list context menu infrastructure. Right-clicking **anywhere** in the file list (on a file, on a folder, or on empty space) shows a context menu. The menu is contextual:

- **On a file/folder:** "New File >" submenu (future: Open, Rename, Delete, etc. — out of scope)
- **On empty space:** "New File >" submenu

Only the "New File >" submenu is in scope for this ticket. The context menu infrastructure should be easy to extend with additional items later.

## Implementation Notes

- File creation itself is trivial (`FileManager.default.createFile`), but wrap it in the `FileService` actor to stay consistent with the off-main-thread architecture
- **Inline rename is new infrastructure.** No inline cell editing exists in the file list today. Cells use read-only `NSTextField(labelWithString:)`. Implementation: temporarily make the name cell's `NSTextField` editable, call `window?.makeFirstResponder(textField)`, and handle `textDidEndEditing` to commit the rename via `FileManager.moveItem`. On Escape, keep the default name.
- Keep the template list hardcoded for now; a future ticket can add user-configurable templates (like the settings panel in the reference screenshot)
- The reference screenshot shows a full settings UI for managing templates — that's out of scope here. This ticket is just the quick-create action with built-in defaults
- The action strip in BreadcrumbBarView should be designed as a generic trailing container — FAYT search button will be added in a separate ticket and should slot in naturally without rework
- BreadcrumbBarView currently has a fixed `heightAnchor` of 22pt — the action buttons should fit within this (use 16x16 SF Symbol icons with `bezelStyle: .inline` + `isBordered: false`, matching the existing `BreadcrumbSegmentView` dropdown arrow pattern)
- No keyboard shortcut for now — access via `+` button and context menu only
- FSEvents not implemented yet — after file creation, explicitly reload the directory and find the new row by URL to select + begin editing
- **Context menu** is built via `menu(for:)` override on `FileListTableView` or by setting `fileTableView.menu` in `FilePanelViewController`. Only "New File >" submenu in scope.
- For `.sh` files, set executable permission via `FileManager.setAttributes([.posixPermissions: 0o755], ...)` after creation
