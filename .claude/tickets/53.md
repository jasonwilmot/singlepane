# Full File & Content Search Engine

**Type:** Feature
**Priority:** High
**Effort:** Large (phased)

---

## TL;DR

Build a full search system — recursive filename search across directory trees + full-text content search inside files. Currently only have in-directory FAYT filtering. This is the Phase 2 critical differentiator per the project spec.

## Current State

- FAYT filters filenames within the **current directory only** (no recursion)
- Glob wildcard + case-insensitive substring matching
- No content search, no index, no SQLite, no FSEvents monitor
- Filter lives in `FilePanelViewModel.applyFilter()`

## Desired Outcome

A search system that can:
1. **Find files by name** across an entire directory tree (recursive)
2. **Search inside file contents** (grep-style full-text)
3. **Stream results** as they're found (never wait for completion)
4. **Cancel mid-search** when query changes
5. (Later) **Indexed search** via SQLite/FTS5 for instant results on large volumes
6. (Later) **Advanced queries** — boolean operators, field prefixes, regex, saved searches

## Implementation Plan (Phased)

### Phase A — Recursive Filename Search
- New `SearchService` actor with recursive walker using POSIX `fts_open`/`fts_read`
- Returns results via `AsyncStream<FileItem>`
- Scope parameter: current folder, subtree, volume, custom paths
- Glob, substring, regex matching modes
- Cancellation via structured concurrency

### Phase B — Content Search
- Extend `SearchService` with content scanning
- Leverage existing `LargeFileReader` (memory-mapped) + `FileEncodingDetector`
- Skip binary files via UTType or magic bytes heuristic
- `TaskGroup` with concurrency limit for parallel file scanning
- Return matches with line number + context snippet

### Phase C — Search Results UI
- New `SearchPanelViewController` or dedicated search results view
- Search bar with scope selector (this folder / subtree / volume)
- Toggle: filename-only vs. content search
- Streaming results table (reuse `NSTableView` pattern)
- Click result → navigate to file (and line for content matches)
- Result count + elapsed time

### Phase D — Indexed Search (Large)
- SQLite + FTS5 database in `~/Library/Application Support/SinglePane/`
- `IndexService` actor (ideally XPC service) for build + maintenance
- FSEvents monitor for incremental index updates
- Initial index build throttled with `IOPOL_THROTTLE`
- Target: full index of 1M file volume in <60 seconds

### Phase E — Advanced Query Syntax
- Boolean: `AND`, `OR`, `NOT`, parentheses
- Field prefixes: `name:`, `ext:`, `size:>1MB`, `modified:<2024-01-01`
- Regex toggle
- Saved searches / smart folders (persist to UserDefaults)

## Relevant Files

- `singlepane/Services/FileService.swift` — existing file operations actor (new SearchService modeled after this)
- `singlepane/FileSystem/DirectoryEnumerator.swift` — POSIX enumeration pattern to extend for recursion
- `singlepane/ViewModels/FilePanelViewModel.swift` — current FAYT filter logic, search results will follow similar pattern

## Notes

- Phases A-C deliver a fully functional "EasyFind competitor" — no index needed
- Phase D is the big lift but makes search instant on large volumes
- Existing `LargeFileReader` and `FileEncodingDetector` services reduce content search effort significantly
- Must respect the 200ms first-result quality gate from the spec
- Consider making search a dockable module per the module system vision
