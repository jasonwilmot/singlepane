# Ghost Breadcrumbs Navigation

**Type:** Feature
**Priority:** Normal
**Effort:** Medium

## TL;DR

Add Directory Opus-style "ghost breadcrumbs" to the path/breadcrumb bar. When navigating up the folder tree, the previously visited deeper path segments remain visible as faded/italic "ghost" crumbs, allowing instant one-click navigation back down to where you came from.

## Current State

- No breadcrumb path bar implemented yet (Phase 1 MVP navigation)

## Expected Outcome

- Breadcrumb path bar displays the current path as clickable segments
- When navigating **up** the tree, deeper path segments from the previous location persist as ghost crumbs (visually distinct — faded, italic, or lighter color)
- Clicking a ghost crumb navigates instantly back down to that folder
- Ghost crumbs update intelligently:
  - Preserved when navigating up (e.g., going from `/Users/jason/Projects/app/src` up to `/Users/jason/Projects` keeps `app/src` as ghosts)
  - Replaced when navigating into a new sibling directory
  - Cleared when navigating to an unrelated path
- Ghost crumbs persist across tab switches (restore ghost state when returning to a tab)

## Key Behaviors (from DOpus reference)

| Behavior | Description |
|---|---|
| **Ghost on navigate up** | Previous deeper path shown as ghost crumbs |
| **Click to restore** | Clicking ghost crumb navigates back to that depth |
| **Visual distinction** | Ghost crumbs rendered in italic/faded style |
| **Smart preservation** | Ghosts preserved going up, replaced on sibling navigation |
| **Segment dropdowns** | Each breadcrumb segment has a dropdown arrow revealing sibling folders at that level, allowing lateral navigation without going up first |
| **Ghost segment dropdowns** | Ghost crumbs also support dropdowns, showing siblings at that depth |

## Notes

- This pairs well with the dual-pane browser — each pane should maintain independent ghost breadcrumb state
- Consider a user preference to disable ghost crumbs (DOpus has `noghostpath` option)
- Keep it performant — ghost state is just path strings, no filesystem lookups needed
