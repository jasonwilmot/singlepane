# Ticket 1: Initial App Scaffolding — Three-Column Layout

**Type:** Feature
**Priority:** High
**Effort:** Large
**Phase:** 1 — Foundation (MVP)

---

## TL;DR

Create the initial macOS app project (XcodeGen + SPM) and scaffold a **configurable, modular** three-column layout for totalcommander. Working SwiftTerm terminal, real POSIX file listings, and markdown preview via swift-markdown + WKWebView. Column order is data-driven via LayoutConfiguration.

---

## Description

Build the scaffolding for the totalcommander file manager. The app window has **three vertical columns** arranged left-to-right (default order, configurable):

### Column 1 — Terminal Panel (default: Left)
- SwiftTerm `LocalProcessTerminalView` + PTY, user's login shell (`$SHELL`)
- Custom NSStackView-based tab bar with "+" (new tab) and "x" (close tab) buttons
- **Tab orientation is configurable**: horizontal (default) or vertical — driven by LayoutConfiguration
- Each tab owns an independent terminal session
- Default: 1 terminal tab on launch

### Column 2 — Dual-Pane File Explorer (default: Center)
- Two file explorer views stacked **vertically** (top and bottom)
- Each explorer has **NSPathControl breadcrumb navigation** showing the current path
- POSIX opendir/readdir/lstat enumeration via FileService actor (off-main-thread)
- NSTableView with columns: name (icon), size, date modified, kind
- Both panes default to ~/Documents
- Divider between panes is draggable

### Column 3 — Preview / Editor / Browser (default: Right)
- **Markdown preview**: swift-markdown parses .md → HTML, rendered in WKWebView with clean CSS
- **Editor**: NSTextView for editing .md files, "Save" returns to preview
- **Browser**: WKWebView with URL bar and back/forward navigation
- Segmented switcher between Preview | Editor | Browser modes
- File explorer selection triggers preview update for .md files

### Modular / Configurable Layout
- Column order is **data-driven** — each column is identified by a PanelType enum and its position is determined by a LayoutConfiguration Codable struct
- Default layout: Terminal | Explorer | Preview — architecture supports reordering
- For now, ship with the default layout only; reordering UI comes later

### Resizing & Collapsibility
- All column dividers are **draggable to resize** via NSSplitView drag handles
- The dual file explorer split (top/bottom) is also **independently resizable**
- **Future-ready for collapse**: NSSplitViewDelegate wired to support future programmatic collapse/hide (no UI for it yet)

## Notes / Risks

- **SwiftTerm dependency**: SPM `https://github.com/migueldeicaza/SwiftTerm` from `1.11.2`. Requires no sandbox.
- **swift-markdown dependency**: Apple's own markdown parser, SPM `https://github.com/apple/swift-markdown`
- **Column proportions**: Default split ~25% / 45% / 30%, all resizable. Explorer top/bottom defaults to 50/50.
- **AppKit-first**: NSSplitView, NSTableView, custom NSView tab bar. SwiftUI for leaf views later.
- **Collapse/hide is future work**: NSSplitViewDelegate supports it, no UI in this ticket.
- **Column reordering UI is future work**: LayoutConfiguration supports arbitrary order, no settings UI yet.
- **User's shell**: Terminal reads `$SHELL` env var for login shell, defaults to `/bin/zsh`.
