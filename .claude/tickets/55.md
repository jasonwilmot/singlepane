# 55 — Syntax Highlighting & Bracket Matching for Framework-Specific Files

**Type:** Feature
**Priority:** Normal
**Effort:** Medium

---

## TL;DR

Add syntax highlighting and bracket matching support for `.vue`, `.svelte`, `.astro`, and other single-file-component formats. These files embed multiple languages (HTML template, JS/TS script, CSS styles) in distinct blocks — the highlighter needs to handle mixed-language contexts.

## Current State

- `.jsx` / `.tsx` already supported (mapped to JS highlighter)
- `.vue`, `.svelte`, `.astro` files open in the editor but get no syntax highlighting or bracket matching
- `CodeSyntaxHighlighter` only supports single-language-per-file highlighting

## Desired Outcome

- `.vue`, `.svelte`, `.astro` files get proper syntax highlighting across all embedded blocks:
  - `<template>` / markup → HTML highlighting
  - `<script>` / `<script lang="ts">` → JS/TS highlighting
  - `<style>` / `<style lang="scss">` → CSS highlighting
- Bracket matching works correctly across all blocks (respecting block boundaries)
- Language detection in `CodeSyntaxHighlighter.languageFromExtension` recognizes these extensions

## Files to Touch

1. **`singlepane/UI/Preview/CodeSyntaxHighlighter.swift`** — Add extension mappings, implement multi-language block detection and per-block highlighting
2. **`singlepane/UI/Preview/BracketMatcher.swift`** — Ensure bracket matching respects language block boundaries
3. **`singlepane/UI/Preview/EditorViewController.swift`** — Verify editor mode routes these file types correctly (code mode, not markdown)

## Notes

- Simplest approach: detect `<template>`, `<script>`, `<style>` block boundaries via regex, then apply the appropriate single-language highlighter within each range
- `lang` attribute on blocks (e.g., `<script lang="ts">`, `<style lang="scss">`) should influence which sub-highlighter is used
- `.astro` frontmatter (`---` delimited YAML/JS at top) is a special case worth handling
- This is a stepping stone toward the Tree-sitter migration (ticket 011) which would handle mixed languages natively
