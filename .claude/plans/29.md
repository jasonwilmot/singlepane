# Fix Terminal Grid Layout at Higher Pane Counts

**Overall Progress:** `100%`

## TLDR
Terminal grid layout produces unevenly sized panes at higher counts (e.g., 15 panes in a 4x4 grid). The `equalizeSplitView` divider positions get overridden by subsequent `NSSplitView` relayout passes. Fix by re-equalizing after the final layout pass and disabling divider dragging in grid mode entirely.

## Critical Decisions
- **No draggable dividers in grid mode** — dragging a divider in one row can't affect other rows (nested NSSplitViews are independent), so resizing just creates misalignment. Users switch to vertical/horizontal mode for manual control.
- **Last row stretches to fill** — incomplete rows (e.g., 3 panes in a 4-col grid) divide their full width equally. No dead space, no column-alignment with rows above.
- **Re-equalize after final layout pass** — the root cause is `self.view.layoutSubtreeIfNeeded()` undoing `setPosition` calls. Move equalization to run after the final layout pass, or use `NSSplitViewDelegate` to enforce equal sizing persistently.
