# Search Engine — Indexed + Raw Filesystem Search

**Overall Progress:** `95%`

## TLDR
Replace the search icon's current FAYT behavior with a real search engine. Clicking the search icon (or Cmd+F) enters search mode — breadcrumbs are replaced by a search text field with toggle icons (filename/content, case sensitive, regex). Results stream into the file list as a two-column table (filename+path, excerpt). Powered by SQLite/FTS5 for indexed search and POSIX `fts(3)` for raw filesystem fallback. Scoped to current directory tree. FAYT filter (click breadcrumb whitespace) stays untouched.

## Critical Decisions
- **Scope:** Search is recursive from current directory, not system-wide
- **FAYT coexistence:** FAYT filter remains separate — breadcrumb whitespace click activates it, search icon activates deep search
- **SQLite C API:** Direct `import SQLite3` (ships with macOS) — zero dependencies, best performance
- **In-process actor:** No XPC for v1 — simpler, sufficient for directory-scoped search. Extract to XPC later if needed
- **Index storage:** `~/Library/Application Support/Velocity/search-index/` — persistent, survives cache purges
- **FDA degradation:** Index what's accessible, skip restricted paths silently
- **Result interaction:** Single-click selects/previews, double-click navigates to parent directory and exits search mode
- **Result columns:** Column 1 = filename + path subtitle. Column 2 = excerpt (content mode). No size/date/kind metadata in search mode
