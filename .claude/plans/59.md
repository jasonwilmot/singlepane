# Search Performance Optimization Plan

**Overall Progress:** `100%`
**Ticket:** `59.md`

## TLDR
Eliminate allocation waste, I/O inefficiency, and SQLite bottlenecks in `SearchService` and `IndexService` to minimize time-to-first-result and maximize raw search throughput on large directory trees (100K+ files). No trigram tokenizer, no `getattrlistbulk`, no parallel traversal.

## Critical Decisions
- **mmap for content search** — 2-5x faster than FileManager full-file reads. Scan mapped bytes, only convert matching line region to String. Fallback to FileManager if mmap fails.
- **`range(of:options:.caseInsensitive)` over `localizedCaseInsensitiveContains`** — speed over locale correctness. Filenames are almost never locale-sensitive.
- **Consolidate text extension sets** — both services have duplicate sets. Extract to a shared `static let` constant.
- **Adaptive batching for fast first paint** — first batch at 5 results, then ramp to 50. Gets pixels on screen faster.
- **Defer URL creation** — `URL(fileURLWithPath:)` does filesystem checks. Store raw path, create URL lazily.
- **Prepared statement reuse is already done** — `indexDirectory()` already prepares once and resets per row. No work needed here.
