# Feature Implementation Plan: Tabbed File Preview / Editing

**Overall Progress:** `100%`
**Ticket:** `.claude/tickets/65.md`

## TLDR
Add multi-file tabs to the preview panel. Selecting a file in the explorer opens a permanent tab (or focuses it if already open). Each tab maintains independent state (file URL, mode, scroll position, dirty text, cursor position). Shared child VCs (editor, markdown preview, code preview, media player) are reused across tabs — per-tab state is saved/restored on switch via PreviewTabState for performance. Two-row layout: file tabs on top, existing Read/Edit mode bar + buttons below.

## Critical Decisions
- **Permanent tabs, not ephemeral**: Every file selection creates a persistent tab. No VS Code-style preview/pin distinction. User closes tabs explicitly.
- **Shared VCs with state save/restore**: One editor, one markdown preview, one code preview, one media player — state is saved/restored per tab on switch. Avoids creating heavy VC instances per tab.
- **Double-click unchanged**: Still opens files in system default app via `NSWorkspace`. No behavior change.
- **Two-row chrome**: File tab bar (full style, close buttons, no "+" button) sits above the existing Read/Edit compact tab bar + toolbar buttons.
- **Close with unsaved changes**: Save prompt dialog (Save / Don't Save / Cancel).
- **Deduplication**: If a file is already open in a tab, focus that tab instead of creating a duplicate.
- **Delegate-managed close**: File tab bar uses `delegateHandlesClose` so async save prompts don't race with visual tab removal.
