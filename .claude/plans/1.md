# Feature Implementation Plan: Three-Column App Scaffolding

**Overall Progress:** `100%`
**Ticket:** `.claude/tickets/1.md`

## TLDR

Scaffold the totalcommander macOS app as a three-column layout: terminal (SwiftTerm + PTY with tabbed sessions), dual-pane file explorer (POSIX enumeration, NSTableView, breadcrumb nav), and preview/editor/browser panel (markdown preview via swift-markdown + WKWebView, NSTextView editor, embedded browser). Column order is data-driven via LayoutConfiguration. All dividers resizable, architecture supports future collapse.

## Critical Decisions

- **Fresh codebase** — write from scratch in the `cli` repo, following patterns from the totalcommander prototype (POSIX enumeration, actor FileService, @Observable ViewModels, programmatic AppKit)
- **SwiftTerm + PTY from day one** — real terminal, user's login shell (`$SHELL`), no placeholder
- **Custom NSView tab bar** — `NSStackView`-based, supports h/v orientation switching via config, "+" and "x" buttons on tabs
- **WKWebView for preview + browser** — markdown rendered via swift-markdown (Apple's parser) → HTML + CSS stylesheet; same WKWebView serves as embedded browser
- **Markdown workflow** — static rendered preview by default, "Edit" button switches to NSTextView, save returns to preview
- **POSIX file enumeration** — opendir/readdir/lstat via actor, off-main-thread, both explorer panes default to ~/Documents
- **LayoutConfiguration** — Codable struct defining column order (array of panel types) and terminal tab orientation; no reorder UI yet, just the data model
- **XcodeGen** — `project.yml` generates `.xcodeproj`, SPM deps (SwiftTerm, swift-markdown)
- **macOS 14+, Swift 6 strict concurrency, no sandbox, single window**
