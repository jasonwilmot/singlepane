# Clickable URLs & File Paths in Terminal — Implementation Plan

**Overall Progress:** `95%`

## TLDR
Make URLs and file paths in terminal output Cmd+clickable. URLs open in the default browser. File paths open a new tab (or reuse current) in the top file pane, select the file, and show it in the preview panel. Full Cmd+hover underline feedback for all link types — OSC 8, auto-detected URLs, and file paths.

## Critical Decisions
- **OSC 8 via SwiftTerm's built-in handler**: SwiftTerm already handles OSC 8 Cmd+click (opens in browser) and Cmd+hover (shows URL tooltip) internally. We don't intercept these — our monitors pass events through when no regex match is found.
- **Auto-detection via local event monitor + public APIs only**: For plain-text URLs and file paths, we use local event monitors with manual grid computation from `terminal.cols`/`terminal.rows`/`bounds` and `terminal.buffer.yDisp` for scroll offset. All internal SwiftTerm APIs (`cellDimension`, `calculateMouseHit`, `displayBuffer`) are avoided.
- **Hover underline for regex-detected links**: Track Cmd+mouseMoved, regex-match at cursor position, draw underline overlay. OSC 8 hover handled separately by SwiftTerm.
- **Always target top file pane**: Terminal is focused during click, so we can't rely on focus state. Top pane is the consistent target.
- **Reuse tab if same directory**: If the top pane's active tab is already in the file's parent directory, just select the file. Otherwise create a new tab.
- **Match all path patterns**: Absolute, relative (`./`), tilde (`~/`), with optional `:line` and `:line:col` suffixes.
- **CWD from OSC 7**: We already receive CWD updates per terminal session. Store per-session for resolving relative paths.
