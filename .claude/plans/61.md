# Search Pipeline Fix + Diagnostics + Loading UX

**Overall Progress:** `100%`

## TLDR
Search results never appear because `FTS_NOSTAT` in both `SearchService` and `IndexService` causes `fts_info` to report `FTS_NSOK` instead of `FTS_F` for regular files — every file is silently skipped. Fix the root cause, add temporary diagnostics logging, add a spinner left of the search field, add a "No results" empty state, and clear the stale (empty) index so the first search falls through to raw search immediately.

## Critical Decisions
- **Remove `FTS_NOSTAT` rather than handle `FTS_NSOK`**: Simpler, correct, and the stat() cost is negligible since both code paths already call `lstat()` separately later
- **Natural index rebuild via raw search fallback**: First search uses raw walk (results within 200ms), background indexing populates the index for subsequent fast searches — no blocking migration at launch
- **One-time stale index clear**: `DELETE FROM files` on first open post-fix so `isDirectoryIndexed` doesn't route to empty FTS5 results instead of the working raw fallback
- **Spinner placement**: Left of search text field in BreadcrumbBarView, swaps between static icon and indeterminate spinner
- **`os.Logger` for diagnostics**: `.debug` level, temporary — visible in Console.app, easy to strip later
